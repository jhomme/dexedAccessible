# v0.3.0 accessibility changes

A list of accessibility changes to make for this release. Items are collected here first and
built later, not implemented as they're added.

1. In the sound selection list, using VoiceOver's own arrow navigation, VO-up, down, left,
   right, moves the VoiceOver cursor but not keyboard focus. The two need to move together.

2. In the function dialog, pressing Escape should put focus on the function button, not
   anywhere else. Addressed differently, 2026-11-14: instead of forcing focus onto the
   function button, VoiceOver now announces which panel focus is returning to (such as
   "Operator 3") before the control JUCE naturally restores focus to. Jim tested this and
   preferred it to the original ask. See deviations.md.

3. The on-screen keyboard's piano keys are only painted shapes, not real controls, so a
   screen reader has no way to say which key is which note or which notes are currently
   sounding. Typing letter keys to play notes, the way some other music programs let you,
   isn't built in either; JUCE, the toolkit this app is built on, can do it, but this app
   never turns it on. Worth designing properly: deciding which letters map to which notes,
   how many notes' worth of range, and pairing it with the Ctrl+K shortcut that already
   jumps focus to the keyboard area, so focus-then-type becomes a real way to play notes
   without a MIDI keyboard, not just a promise in a commit message.

4. No way to type an exact number into a slider or knob with the keyboard. Right now the
   only way to set a value without a mouse is nudging it with the arrow keys. Surge XT has a
   feature for this: press Enter on a focused control, a small dialog opens, type the number,
   press Enter again to commit, or Escape to cancel. Confirmed real by reading Surge's own
   accessibility and user manual pages, not just going on memory. This would work the same in
   any host or format, unlike the CLAP typed-parameter fix, which only matters inside a host's
   own generic parameter list. Worth knowing before building it: JUCE's own built-in slider
   text box is reportedly bad for this, several JUCE forum threads describe it as buried
   inside private sub-parts of the Slider component and hard for a screen reader to reach.
   Surge most likely built their own popup for this rather than relying on that. Doing the
   same here would mean a new small component, not turning on an existing JUCE feature.
